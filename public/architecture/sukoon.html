System Architecture

How the pieces connect

A single Next.js application hosts both the admin interface and the public REST API. Supabase provides the database, authentication and file storage.

Clients

  • Public website — visitors browse listings, works, reviews
  • Admin panel — owner logs in at /admin
⇄HTTPS

Next.js 16 · React 19 · TypeScript

  • /api/* — read-only REST endpoints, secured by API key
  • Server Actions — all admin create / update / delete
  • Zod validation on every form
  • Auth guard on every admin page + session refresh
  • Cache revalidation after each change
⇄Supabase SDK

Supabase

  • PostgreSQL — properties, images, inquiries, works, reviews, transactions
  • Auth — email + password admin sign-in
  • Storage — properties and works buckets

Admin write path

Owner fills form → Zod validates → Server Action writes to Postgres → images go to Storage → pages revalidate → website shows the change.

Public read path

Website sends x-api-key → API checks key → only published data is queried → internal IDs stripped → clean JSON returned.

Public API

How the website gets its data

All endpoints are GET. Property and works endpoints require an x-api-key header; only published listings are ever returned.

Endpoint Purpose Details
/api/properties Property Listing page Pagination (page, limit); filters: category, city, min/max price, configuration, furnished, exclude_id; sort: latest, price_asc, price_desc. Returns cover image + gallery + page meta.
/api/properties/grouped Home page "What are you investing in?" Latest 3 published listings for each of the 5 categories in one call.
/api/properties/[publicId] Property detail page Single listing by public ID with all images; 404 if missing or unpublished.
/api/works Our Works page Projects newest first, with media (images / videos).
/api/reviews Home testimonials Name, quote, avatar, newest first. CORS-enabled for the frontend.
Data Model

What's stored

Six tables in PostgreSQL plus two storage buckets.

properties

Title, description, price, location, city, village, area, survey no., category, amenities, configuration, floor, zone, fencing, related listings, published flag, timestamps.

property_images

Image URL + display order, linked to a property. Removed automatically with it.

inquiries

Visitor name, phone, email, message, linked property. Validated server-side.

works

Title, category, location, status, description and a media list (URL, type, storage path).

reviews

Name, role, quote, avatar URL.

transactions

Credit / debit, title, source, amount, date, and link to the credit it draws from.

Security & Reliability

Built to be trusted


Protected admin. Every admin page checks the signed-in user; visitors only ever see the login screen.
API key gate. Public data endpoints reject requests without a valid x-api-key (401), and fail safe if the key is not configured.
Published-only exposure. Drafts never leave the admin; internal database IDs are stripped from API responses.
Validated input. Zod schemas enforce lengths, formats and positive numbers for properties, inquiries, reviews, works and transactions.
Clean deletes. Removing a listing or work also deletes its files from storage — no orphaned media.
Session safety. Sessions refresh on every request and the panel logs itself out before expiry.
