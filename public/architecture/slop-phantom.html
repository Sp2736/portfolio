Your AI assistant just wrote pip install.
Did it just install malware?

Every AI coding assistant occasionally suggests a package that doesn't exist — or one that looks almost identical to a real one. Attackers know this, and they've started registering those exact names first.

01 — The Threat

Two doors into the same room

Phantom squatting and slopsquatting both end with a developer installing a package they never meant to trust. They just get there differently.

Phantom Squatting

Attacker bets on a typo

A malicious package is pre-registered on npm or PyPI under a name that looks or sounds like a popular one. No AI required — it just waits for a developer to mistype, misremember, or misread a name.

pip install reqeusts # real package: requests
When it strikes
  • Fast, manual typing under time pressure
  • Copying a package name from memory, not documentation
  • Autocomplete suggests the wrong entry from history
Slopsquatting

Attacker bets on the model

An LLM confidently suggests a package that sounds plausible but was never published. Attackers watch for these recurring hallucinations and register the name before a developer does — turning the model's confidence into the attack surface.

import fastjson-utils # hallucinated by the model, now real — and hostile
When it strikes
  • Copy-pasting AI-generated code straight into a project
  • Reaching for an unfamiliar or newly-released library
  • Trusting the model's suggestion because "it compiled"

03 — The Fix

Give the agent an instructions.md it can't skip

The same pattern Claude's own agents use: before acting, the agent reads a project-level instructions file that spells out exactly how to verify a dependency — instead of trusting whatever it just generated.

instructions.md
1## Dependency Verification Rules
2
3- NEVER run an install command for a package
4 the agent itself just suggested, without checking it first.
5
6- MUST confirm the package exists on the official
7 registry (PyPI / npm) before installing.
8
9- MUST check publish date, maintainer history, and
10 download count. Flag anything < 30 days old
11 or with near-zero downloads.
12
13- MUST compare the name against known popular
14 packages for near-identical spelling.
15
16- IF any check fails: stop, explain why, and ask
17 the developer to confirm manually.
18
19- LOG every check performed for later audit.

02

Agent reads instructions.md first

Before running the install, it consults the project's standing rules — not its own judgment in the moment.

03

Runs the checklist against the registry

Existence, age, maintainer, download count, name-similarity — each rule checked in order.

04

Blocks or proceeds — and says why

A failed check halts the install and surfaces the specific reason to the developer, instead of failing silently or installing anyway.

Closing

The model doesn't need to be right every time.
The agent just needs to check before it trusts itself.
