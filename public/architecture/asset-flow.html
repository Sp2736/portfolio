AssetFlow

An enterprise asset & resource management ERP module, built for the Odoo Hackathon (July 2026, 8-hour online format). Tracks physical assets and shared resources end-to-end — departments, categories, employees, allocation, booking, maintenance, and audit — for any organization: offices, schools, hospitals, or factories.

Mission

Reduce manual asset-tracking overhead by giving an organization one place to register assets, allocate and transfer them without double-booking, run maintenance and audit workflows with server-enforced rules, and see utilization through reporting — rather than spreadsheets and word-of-mouth.

Explicitly out of scope

Purchasing, invoicing, and accounting. Acquisition cost is stored on each asset only for reporting/ranking — it is deliberately never wired into any accounting logic.

Basic operating workflow

Admin sets up departments, categories and roles → Asset Manager registers assets (status: Available) → assets are allocated, or flagged as shared resources subject to booking → transfer requests resolve reallocation conflicts → maintenance requests move a damaged asset through an approval workflow before it's marked Under Maintenance → periodic audit cycles verify presence/condition per department → every state change writes to the activity log and can trigger a notification.

System architecture & data flow

Single Next.js repository for both frontend and backend. Supabase provides Postgres, Auth, and row-level security — there is no separate backend service by design.

Auth flow

Signup only ever creates an Employee-role row (DB trigger handle_new_user() on auth.users insert). Role escalation to Department Head / Asset Manager happens in exactly one screen, gated to Admin.

Conflict prevention

Booking overlap is rejected by a Postgres EXCLUDE constraint using btree_gist — not a client-side calendar check. Touching slots (one ends exactly as another starts) are valid.

Lifecycle integrity

A before update trigger on assets whitelists valid status transitions (e.g. Disposed is terminal) — an arbitrary client PATCH can't skip states.
